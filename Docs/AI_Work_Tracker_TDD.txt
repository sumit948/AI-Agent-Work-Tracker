01  HIGH-LEVEL ARCHITECTURE

The system is composed of five layers, each with a clearly defined responsibility. Requests flow top-down from the React frontend through the Spring Boot API layer, through the AI service, and are persisted in Supabase PostgreSQL. AWS handles deployment and optional file storage.

FrontendReact.jsUI, user interactions, API calls, charts, dashboard, chat interface
API LayerSpring BootREST APIs, business logic, JWT auth, AI orchestration, data processing
AI ServiceLLM APIConvert raw text → structured JSON, generate summaries, answer queries
DatabaseSupabase (PostgreSQL)Persist users, raw logs, structured logs, reports - accessed via JPA
InfrastructureAWS + DockerEC2 for backend deployment, Docker container, S3 (optional), CloudWatch logs

2.2  Backend - Java Spring Boot
Spring Boot is the backbone of the system. It owns all business logic, security, AI API calls, and data persistence. The frontend is kept thin - Spring Boot does the heavy lifting.

Core Responsibilities
• Expose all REST APIs consumed by the React frontend
• Handle JWT-based authentication and route authorization
• Receive raw work log text and save it to the database
• Call the LLM API with a structured prompt and parse the JSON response
• Save the AI-structured output (tasks, categories, hours) to the database
• Aggregate data for daily/weekly reports and return to frontend
• Handle chat queries by building context from past logs and calling the LLM

Spring Boot Project Packages
src/main/java/com/worktracker/
  controller/     → REST API endpoints (AuthController, LogController, etc.)
  service/        → Business logic layer
  repository/     → JPA interfaces for DB access
  entity/         → JPA entity classes (User, RawLog, StructuredLog)
  dto/            → Request / Response DTOs
  config/         → Security config, JWT filter, CORS config

2.3  AI Layer - LLM Integration
The AI layer is a service class inside Spring Boot - not a separate microservice. When a raw log is submitted, the AIService builds a prompt, calls the LLM API (OpenAI / Gemini), and returns a structured JSON response that is then parsed and saved.

Example - Input / Output
Input (raw user text):
"fixed login bug and worked on payment API"

Prompt sent to LLM:
Convert the following work log into structured JSON.
Return a JSON array of tasks with: title, category, hours.
Categories: Bug, Feature, Meeting, Review, Other.

Input: "fixed login bug and worked on payment API"

LLM Response (structured JSON):
{
  "tasks": [
    {
      "title": "Fix login bug",
      "category": "Bug",
      "hours": 2
    },
    {
      "title": "Payment API development",
      "category": "Feature",
      "hours": 3
    }
  ]
}

Important Design Rules
• Always validate AI response - check for valid JSON before saving
• Add fallback: if AI fails, save raw log with status PENDING and retry
• Set a timeout on LLM API calls (5-10 seconds) to avoid blocking
• Log every LLM request/response for debugging and audit

2.4  Database - Supabase (PostgreSQL)
Supabase provides a hosted PostgreSQL database. Spring Boot connects to it using Spring Data JPA and a standard JDBC connection string. DBeaver can be used for direct visual inspection of tables during development.

Connection Setup
# application.properties
spring.datasource.url=jdbc:postgresql://<supabase-host>:5432/postgres
spring.datasource.username=postgres
spring.datasource.password=<your-password>
spring.jpa.hibernate.ddl-auto=update
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect

03  END-TO-END REQUEST FLOW

Below is the complete journey of a work log entry - from user input to structured storage and display.

1. User types raw notes into the Work Log Entry page (React)
2. React calls POST /api/logs with { userId, rawText } - JWT in Authorization header
3. Spring Boot AuthFilter validates the JWT token
4. LogController passes the request to LogService
5. LogService saves the raw log to the raw_logs table in Supabase
6. LogService calls AIService.processLog(rawText)
7. AIService builds the prompt and calls the LLM API (OpenAI / Gemini)
8. LLM returns structured JSON (tasks, categories, hours)
9. AIService parses and validates the JSON response
10. LogService saves each structured task to the structured_logs table
11. Response (structured tasks) returned to React frontend
12. React updates the Dashboard and Reports pages with the new data

06  AI INTEGRATION FLOW - DETAILED

The AI integration is handled entirely within the Spring Boot backend. The frontend never calls the LLM directly - all prompts, API keys, and response parsing are server-side.

Step-by-Step Flow in AIService.java
13. Receive rawText from LogService
14. Build structured prompt (see template below)
15. Call LLM REST API with API key from environment variable
16. Receive raw text response from LLM
17. Extract JSON block from response using regex / string parsing
18. Validate JSON structure - check required fields exist
19. If valid: return parsed task list to LogService
20. If invalid or error: log the failure, set ai_status = FAILED, return empty list

Prompt Template
You are a work log parser. Convert the input into structured JSON.

Rules:
- Return ONLY valid JSON, no explanation text
- Categories must be one of: Bug, Feature, Meeting, Review, Other
- Estimate hours based on typical task complexity
- If multiple tasks, return all in the tasks array

Format:
{ "tasks": [{ "title": "...", "category": "...", "hours": 0.0 }] }

Input: {rawText}
